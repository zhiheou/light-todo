### 🆕 v3.9.22 修了一个"最伤人"的 bug

**用户报**：「明天要跟进vivo锁机事项」→ 轻宜回「好，我帮你记下了」→ **待办里根本没有**。

**根因不在对话大脑**（复现原话，它确实建了任务、确实写盘了），而在**桌面版双窗口**：

```
桌宠窗口 ──写盘──→ localStorage（两窗口共用）──→ 主窗口不知道
                                                    │
                        主窗口每 30 秒 / 每次获得焦点，拿【服务器旧数据】
                        整份替换本地并回写 ──────────┘
```
**→ 桌宠记的待办存活最多 30 秒。**
**→ 用户去主窗口找它，那个"点一下窗口"的动作正好触发拉取 —— 所以永远找不到。**

**🔴🔴 第一版修完还是没好** —— 真事故路径在**登录那一刻**（主窗口会话过期、停在登录页）：
`handleLogin()` 开头 `resetAllLocalData()` 清空 state → 持久化 effect **下一帧就把 `[]` 写进磁盘**，
在 `await` 解密期间把桌宠记的那条**连同水位痕迹一起从磁盘删掉了**。
光记住水位没用，必须**不让这次空写落盘**。

修法（12 条，两轮）：`src/lib/syncLock.ts`（新）
—— 写盘即登记水位 + 跨窗口 `storage` 互听 + 归属键防串号 + **认证期间落盘闸门**。

**⚠️ 三条硬规矩（改同步逻辑前必读，详见 07-KB §二·八）：**
1. 给"防覆盖判据"加水位时，**必须同时确认"水位不会被读取动作自己抬高"**（否则多端同步静默失效）
2. **"清空界面残留"≠"删用户数据"** —— `resetAllLocalData()` 是前者，但持久化 effect 分不清，
   会把前者当后者执行。**给"清空"配持久化 effect 时必问：这次写会不会删掉用户的真数据。**
3. **闸门必须在更新 `lastWritten` 之前返回**，否则关闸后真正的写会被去重逻辑当成重复而跳过，
   磁盘永远停在旧值。

**真机验证（真实 Electron 双窗口，三条路径全过）**：
① 桌宠写 → 已登录主窗口立刻显示 ② 主窗口停在登录页时桌宠写 → 重新登录后仍在
③ 全新设备登录 → 仍能拿到服务器数据（多端同步没坏）

**→ 纯网页改动，用户关掉程序重开即可，不用重装。**

### 🆕 v3.9.22 第二个事故：Mac 装了打不开（两个芯片的包互相覆盖）

**用户报**：「显示你无法打开应用程序清代版，因为这台mac不支持应用程序」（2018 款 Intel MacBook Pro）

**真凶**：`mac.artifactName` 是 `light-todo-setup-${version}-mac.${ext}` —— **没带 `${arch}`**。
`target.arch` 明明配了 `[x64, arm64]`，但两个包**名字撞了，后者覆盖前者**，
线上只剩一个，而"活下来"的恰好是 **arm64**（Apple 芯片专用）→ Intel 机器直接拒绝打开。

**🔴 这类 bug 的可怕之处：每一步都"成功"了** —— 构建成功、上传成功、下载成功、
页面正常、按钮能点、文件名看着也正常。**没有任何一处会报错。**

**修**：artifactName 加 `${arch}`；下载页按芯片自动挑（`pickMacDownload`）；
`release.sh` 取回**两个** Mac 包一起传 R2，缺一个就中止。

**⚠️ 挑芯片的两个坑（已加测试锁死）**：
1. 不能拿 UA 里的 `Intel Mac OS X` 当判据 —— **两种芯片的 UA 都有这串**（历史遗留）
2. 判不出时**必须默认 Intel** —— Intel 包在 Apple 芯片上能跑（Rosetta），
   反过来 arm64 包在 Intel 机器上**根本装不上**。安全性是不对称的。

**验证**：二进制层面验过 —— x64 包解出的 Mach-O cputype 是 `0x01000007`（x86_64）✅

**🔑 发版规矩（本次新增）**：
- **一个构建产物有多个变体（架构/渠道）时，文件名必须能区分**。只"打两个包"不够 —— 名字撞了等于只打了一个。
- `bash desktop/scripts/release.sh` 现在会**自动从 GitHub Release 取两个 Mac 包**，
  少一个就直接中止（不会再出现"以为发了、其实只发了一半"）。
- ⚠️ **Mac 改动 → 用户必须装新版**（跟纯网页改动不一样）。

```bash

```
⚠️ **`--remote` 必须带**（否则传到本地模拟目录）

→ **`npm test` 直接启动失败**。
**→ 跑完 `wrangler <cmd>` 必须 `git status` 检查有没有被偷改文件。**

### 测试方法（血泪）
1. **UI 问题验收必须用真实鼠标**（PowerShell `mouse_event`），`element.click()` 绕过命中检测
2. **必须连到用户正在运行的程序上测**：`--remote-debugging-port=9333` + CDP（`ws` 模块）
3. 测试脚本的鼠标移动要在**一个 PowerShell 进程内**完成（每步起一个进程有几秒延迟）
4. 涉及"能不能点"的改动 → 用 `pet-debug-state` IPC 读主进程状态，**别猜**

### 其他
