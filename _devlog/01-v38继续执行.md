## A. 什么是"git remote 里明文嵌着 GitHub PAT"（大白话）

`git remote` 是"这个项目要上传到哪个远程仓库的**地址**"。地址本来应该是：
```
https://github.com/zhiheou/light-todo.git
```
但现在它是：
```
https://zhiheou:github_pat_11CE6VSQ…（一长串）@github.com/zhiheou/light-todo.git
```
那串 `github_pat_…` 就是 **GitHub 个人访问令牌（PAT）**——相当于"上传代码的密码"，夹在地址里了。
后果：这台电脑上**任何能看到项目配置的人/程序**（如 `.git/config`），一眼就能抄走这个密码，冒充你往仓库传代码。它不是"别人的 token"，是**你自己 GitHub 账号的钥匙**，等于把钥匙挂在门口。

**处置选项（需要你在 GitHub 网页上配合，我没法替你点）**：
1. **换掉它（推荐）**：去 https://github.com/settings/tokens 删除/轮换这枚 → 再告诉我，我把地址改干净 / 或改用 ssh 钥匙（配好后更省心、永不夹密码）。
2. 现在这项目仓库是**公开的**，读不用钥匙；钥匙只用于"上传"。所以只要你不 push，就不触发它。
3. 这串 token 还曾出现在聊天记录里 → **强烈建议轮换**（历史记录里只要出现过，都当已泄露）。

### C0. A4｜闲置"卡卡动"去抖（commit `98e0e74`）
**症状**：桌宠闲置时会"一卡一卡"地换形态，尤其聊天时更明显。
**根因（读代码定位）**：闲置自动换形的定时器，把 `expression`（主导表情）放进 React 依赖数组。聊天时表情在 idle↔typing 频繁切换 → 定时器被**反复重建**、节奏全乱；且聊天/试玩/菜单等"不该打扰"的场景也没暂停。
**改法**（`PetShell.tsx`）：
1. 新增 `liveExpr` ref 记录"当前表情最新值"（同步于 prop，但不触发重渲染）——长周期判断只读 ref，不再因 expression 抖动重建。
2. 定时器只在 `skin.autoStates` / `previewState` / `chatOpen` 变时才重建。
3. `chatOpen`（聊天面板开）真正从父组件 MascotAssistant 传入（`chatOpen={open}`），聊天期**暂停**自动换形；关闭后从完整 16-28s 间隔重新起算 = 天然去抖。
**验证**：tsc ✅ build ✅；代码逐行复读确认无死路。
> 注：A1-A3（甩飞二次触发/面板层级/屏占比）在上一轮会话崩溃前已改好、由我核实后提交为 `4ef6872`（见 §B）。A1-A3 内容是：petPhysics 加水平空气摩擦、面板 z-index 47→65、尺寸按屏宽 9% + resize 监听。

### C1. B｜吉祥物删待办首次授权（commit `44f4b0b` + `9f73624` 打磨）
**需求**：用户第一次让 AI 删待办，得先授权（防"它自作主张删数据"）；按空间各自记住。
**实现（3 文件）**：
- `mascotBrain.ts`：新增 `needDeleteGrantReply()`（授权话术）、`isGrantDeleteIntent()`（识别"允许删除"意图）。
- `App.tsx`：新增每空间授权状态 `deleteGranted`，localStorage key `lighttodo:pet-delete-grant:v1.<work|personal>`；`grantDeleteToAssistant()` 落库。
- `MascotAssistant.tsx`：本地小脑返回 `confirm`（要删某条）时，若**未授权** → 不进入删除确认，先进入 `awaitingGrant` 态请求授权（面板出「允许删除/取消」chips）；授权后落库记住，再进入正常"确认删这条"→"是，删掉"→真删。`deleteGranted` 由 App 传入。
- 打磨（`9f73624`）：授权等待期输入其它话 → 给一句轻提示，不再静默吞。
**边界确认**：人类在列表点删除**不受影响**（那是用户直接操作，本就明确）；授权只针对 AI 发起的删除。删除执行仍走 App `deleteTask`（含 toast 撤销），未重复造轮子。
**验证**：tsc ✅ build ✅。

### C2. C｜情绪陪伴（commit `ec2ad14`）
**需求**：桌宠要有情绪价值——你说烦/累/难过，它先共情，不急着给建议；并把心情记下来可回看。

  - `tryAddMemo()`：本就"记到备忘录"的内容若带情绪词 → 自动补 `#心情`。
  - `answer()` 分支顺序：删除→查询→记备忘→建待办→**情绪**→问候（情绪兜在任务/备忘规则后，避免误抢"明天开会"这类）。

- DeepSeek system 提示（个人/工作都加）："用户在倾诉心情/压力时，**先共情安抚，不要急着给建议**"。
**验证**：tsc ✅ build ✅。
