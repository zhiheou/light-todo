## 一、会丢东西的（6 条，最严重）

**1. 个人空间的数据在本机没有备份，关得快一点就整段丢** ⭐ 已验证
- 什么情况：在个人空间新建/修改后 **1 秒内**关掉页面或程序，或者**断网时**编辑 —— 刚记的整段消失，重开也找不回来。本机完全没副本，唯一去处是云端。
- 为什么：`App.tsx:278-281` 只给**工作空间**注册了本机存档（`saveTasks("work")` / `saveWorkMemos` / `saveWorkDimensions` / `saveWorkGoals`），个人空间四样一个都没有。`saveTasks("personal")` 全仓库只有桌宠窗口那一处，而桌宠窗口被 `desktop/main.js:247` 钉死为 `mode=work`。
- 怎么修：给个人空间补上和普通待办同构的本机存档；关页前补传一次。

**2. 登录/重开应用时，个人空间、维度、目标可能被清空，还把云端那份也覆盖掉** ⭐ 已验证
- 什么情况：本机有一处改动比云端新时（例如主窗口停在登录页、你在桌宠里记了一条），之后登录/自动登录会走「留住本机」分支 —— 但这个分支**只恢复工作空间的四样**（`App.tsx:904-909`），个人空间四样从未赋值 → 空数据在 800ms 后被上传 → **服务器上那份也被覆盖成空**。
- 同型问题：`handleSessionRestore` 的分支（`App.tsx:985-993`）连 `workDimensions`/`workGoals` 都不恢复。
- 雪上加霜：`dimensionsLocal.ts:39-41` / `goalsLocal.ts:17-19` 的写盘**没有 authTransition 闸门**（v3.9.22 只给 tasks/memos 加了），所以 `resetAllLocalData()` 清空 state 后下一帧就把 `[]` 写进磁盘，等分支回头 `loadWorkDimensions()` 读到的已经是自己抹掉的空盘。
- 怎么修：两处「留住本机」分支补全个人空间四样（从本次登录已解出的云端数据取回）+ 补 `setWorkDimensions`/`setWorkGoals`；给维度/目标加早退闸门。

**3. 关掉主窗口只留桌宠后，到点提醒一个都不会响** ⭐ 已验证
- 什么情况：桌面版最常用的用法（关主窗口、留桌宠）下，到点提醒**不弹、不响、桌宠头顶也不冒泡**；更糟的是这条提醒会被 `notified.current.add()` 记成「已提醒」并 `saveNotified` 存盘 → **以后也不会补**，等于永久错过。
- 为什么：`computeDueReminders` 全仓库只出现在 `App.tsx:1252-1268` 一处，而它所在的 `App` 组件就是主窗口。`DesktopPetApp.tsx` 里**零提醒逻辑**（已 grep 确认）。
- 怎么修：把提醒轮询搬进桌宠窗口（或主进程），不依赖主窗口。

**4. 网络慢或在另一台设备上刚用过时，正在改的内容会被旧数据盖回去**
- 什么情况：弱网下点一下窗口触发拉取，在请求飞行途中你改了任务 → 返回时守卫失效 → 服务端旧数据整份铺回。
- 根因：水位快照 `localMark` 在 `fetchWorkspace()` **之前**取（`App.tsx:1176`），而两处守卫比较的是 `localMark > lastPullStarted.current` —— 两个值在整个拉取期间都不变，**条件恒为假**。
- 怎么修：解密返回后用**当下**水位重算一次再判断。

**5. 在桌宠里勾完成、改日期，之后可能被云端旧数据改回去**
- 什么情况：桌宠的 `onToggleTask`/`onUpdateTask`（`DesktopPetApp.tsx:157-159`）只改 `completed` 和 patch，**不写 `updatedAt`** → 水位抬不动 → 主窗口重开/重新登录时被判成「本机不比服务器新」→ 改动被盖回；被删的任务也可能复活。
- 附带：这样完成的任务不显示「完成于今天」，复盘页「今日完成」也不计数（`completedAt` 同样没写）。
- 怎么修：复用 `lib/tasks` 的 `toggleCompleted`；`onUpdateTask` 补 `updatedAt`；删除走同套登记。

**6. 本机存储写满时，界面崩到「出错了」页，改动还悄悄存不上**
- 什么情况：`saveTasks:221` / `saveMemosByMode:105` 是**裸 `localStorage.setItem`**，无 try/catch。写满（或 iOS 隐私模式）时抛错 → 冒泡到 ErrorBoundary → 全屏「出错了」。
- 更坏：`lastWritten` 在 `:217` 已经更新，异常在 `:221` 才抛 → 同内容被去重跳过、**永不重试** → 用户看到「改了、刷新又变回去」。
- 怎么修：写盘包 try/catch + 提示「本机存储空间不足」+ 保留重试。

## 二、隐私（1 条，信任问题）

**7. 界面写着「本机智能 · 数据不出空间」，实际会把你的话传到服务器**
- 实际行为：① 个人空间里它答不上来的话 → `POST /api/fallback-log`（原话截前 120 字）到自家服务器；② 工作空间聊天 → 最多 30 条**待办标题**发给**第三方 AI（DeepSeek）**。
- 而 `MascotAssistant.tsx:913` 那行小字是**静态写死**的，两种模式共用、不随实际链路变化。
- 上传开关 `isUploadOn()` 默认就是**开**（只有显式存过 `"0"` 才 false）。
- 证伪员结论：属实，「文案承诺与实际不符」是可感知的信任风险。
- 怎么修：小字随实际链路变（要走云端就写「将使用云端 AI，内容会离开本机」）；上传开关默认改关，首次用到时明示询问一次。

## 三、聊天助手：记错、改错、不听指挥（10 条）

**8. 说「周报还没写完」，它会把任务标成已完成** ⭐ 高
- `mascotBrain.ts:277` 的 `undoWord` 收了「没弄完/还没弄/还没写」，但**没写「（还）没写完/（还）没开完」**；而 `doneWord` 那边有「写完/开完」。于是下班前一句进度汇报，任务被直接划掉。
- 修：`undoWord` 补「没写完/还没写完/没开完/还没开完/没做好」。

**9. 说「买一点水果」，被当成「凌晨 1 点」，提醒设在昨天深夜** ⭐ 高
- `nlp.ts:204` 把任何紧邻「点/号/日」的 1-3 位中文数字先转阿拉伯数字 → 「一点」→「1点」。实测：「买一点水果」→ 今天 01:00、提醒落在昨天 23:50（已过去，永不响）；「买两斤排骨」→ 02:00；「明天两点见」→ 凌晨 02:00。
- 修：转换前排除「一」「几」（或要求「数字+点」后面不接量词/名词才算时间）。

**10. 它教你回「记下来」，你照做，却建出名叫「下来」的垃圾任务** ⭐ 高
- `mascotBrain.ts:518-523` 的 `stripHelp` 开头外壳规则对「记下来」只吃掉一个「记」字，把「下来」留成正文。
- 实测：「买菜」→ 它回「回『记下来』我就建」→ 用户照做 → 任务标题 =「下来」；「帮我记下来，明天开会」→「下来， 开会」。
- **这是它主动教会用户说的话，命中率极高。**
- 修：整体剥离 `/^(?:帮我|给我|替我)?\s*(?:记(?:下来|下|一下|一笔)|记录|记事)/`。

**11. 删除确认框里点「删除」，永远删不掉** ⭐ 中（100% 复现）
- 按钮发的是「是，删掉」，而 `readConfirm` 收紧成了整句锚定（`mascotBrain.ts:769` 的 `YES_FULL`）→ 返回 null → 落到「当普通对话处理」，回你「抱歉，我没找到要删的任务」。只有手打「好」才能删。
- 修：按钮改发它认的整句（如「删吧」）**或**把「是，删掉」加进 `YES_FULL`。⚠️ **不要动 `localOnly`/`choices`/`pendingChoices` 三道防幻觉闸门本身。**

**12. 「下周交房租」「两周后」不给日期，「下礼拜五」认不出**
- `nlp.ts:127` 的 `STRIP_RULES` 为这些词留了**剥离位**（标题清了一半），但 `parseQuickAdd` 里**没有任何分支接住它们** → 样式清了、数据全丢，保存后永远不知道是哪天。实测「下周交房租」「两周后交房租」「两星期后」「下下周」「隔周开会」全为「未设日期」。
- 另有算错：「这个月最后一天」→ 被当「下月同日」。「礼拜五」不在星期词表（只认周/星期）。
- 修：补「下周=下周一」「N 周后=+7N 天」「月末最后一天」，星期词表加「礼拜」。

**13. 一句话说两件事，只记第一件**
- 「明天开会，另外记得买牛奶」→ 一条「开会，另外记得买牛奶」；「明天开会，后天交材料」→ 只取第一个日期，后天的信息丢了。
- 修：建任务前按「，。；另外/还有/顺便/也/、」切句，多段分别建，回执列全部。

**14. 「刚说的那条删了」「把它删了」—— 一律回「没找到」**
- 改任务早就支持指代，**删除和完成没跟上**（`mascotBrain.ts:188-192、315`）。
- 修：指代类说法在未完成任务只有一条时直接进操作，多条列出来让用户选（照改任务的做法对齐）。

**15. 「帮我查一下交房租」→ 回「这些我可帮不上忙」**
- `mascotBrain.ts:790、812、831`：光秃秃的「帮我查」在离题拦截名单里；「查一下明天的安排」不加「帮我」就正常。
- 修：把「帮我查」从拦截名单去掉（或要求后面跟天气/新闻这类**外部话题**才拦）。

（另有多条同类，明细见本报告末「完整清单」）

## 四、桌面 / 手机体验（7 条）

**16. Mac 用户永远收不到版本更新** ⭐（已独立确认）
- 更新源上没有 `latest-mac.yml`（`release.sh` 只传 Windows 的 `latest.yml` + 两个 mac zip），`grep latest-mac` 全仓库零命中。
- 而且 mac 自动更新在架构上就**不可能工作**（Squirrel.Mac 要求代码签名，我们是故意不签名的）——已查证 Electron 官方文档与 `SQRLUpdater.m` 源码。
- 现状：Mac 用户**连「有新版本」的提示都收不到**，唯一入口是菜单栏右键。
- 怎么修：Mac 加应用内「发现新版本 → 打开下载页」的横幅（Windows 继续用 electron-updater）。

**17. 「注视跟随」等 4 个开关是假开关**
- `PetConfigPanel.tsx:25-33` 渲染了 7 个行为开关，但全代码库**只有 `draggable`、`blink/breathe` 被真正读取**；`look`/`drift`/`idleActs`/`follow` 除了类型定义**零引用**。注视跟随的 `pointermove` 监听（`PetShell.tsx:639-660`）无条件运行，从不检查开关。
- 用户勾选/取消写进 localStorage 但没人消费 —— 「开关随便点、行为永不变化」。
- 修：要么读这些选项，要么从面板删掉。

**18. 中文输入法打字时按回车会提前提交拼音/半成品** ⭐ 高频
- `MemoList.tsx:84-89`、`AddDialog.tsx:156-161`、`MascotAssistant.tsx:1109-1111` 三处 `onKeyDown` 只看 `e.key === "Enter"`，**没检查 `e.nativeEvent.isComposing`**。
- 电脑上用拼音输入法的人，每次用「回车」上屏都会踩中：候选还没上屏就把「mingtiankaihui」当正文提交了。
- 修：三处开头加 `if (e.nativeEvent.isComposing) return;`

**19. 手机上系统键盘弹起时盖住聊天输入框**
- `styles.css:3711-3717` 面板固定在屏幕底部；`index.html:5` 的 viewport 没有 `interactive-widget` → 键盘弹起时不避让。

**20. BloubAvatar 每帧把 SVG 全部推倒重建（30fps 常驻）**
- `BloubAvatar.tsx:169` 每帧 `g.innerHTML=""` 再 `createElementNS` 重建全部 path。规模不大（12 条 path），属「可优化的小浪费」，桌面版常驻时会一直吃一点 CPU。
- 证伪员注明：报告里那句「CPU 5%-15%」**未经证实**，不要当数据引用。

**21. 单 chunk 打包：下载页也被迫加载整个应用**
- `dist/assets/` 下只有一个 JS（427KB）+ 一个 CSS（67KB），`main.tsx:3-5` 三个根组件全是静态 import。访问 `/download` 会先加载执行整包。

**22. 登录后的短暂窗口里，鼠标事件全部漏给底下的主窗口**
- 主进程收到 `reportLoginState(true)` 就 `show()` 桌宠窗（`App.tsx:1141`），但桌宠窗页面还没跑完启动、没上报 hitbox → 没有 hitbox 就一律 `setIgnoreMouseEvents(true)` 全穿透 → 那 1-3 秒里点哪儿都落到主窗口。
- 变体：校验失败（断网）时那条错误分支**不调 `reportLoginState(false)`**（`App.tsx:1120-1129`），漏点状态会**一直保持**。
- 连带：个人空间的访问码键盘弹在桌宠窗上，用户鼠标一动就点到背后 —— 输入框失焦。

## 五、账号（2 条）

**23. 注册半途失败时，桌宠记的待办会被删掉（且从未上传过）**
- `handleRegister` 比 `handleLogin` 少了**两道防护**：没有 `watermarkBeforeReset()` 快照；闸门只拦「写盘」，拦不住闸门关闭后空 state 触发的自动保存把 `[]` 落盘。
- 用户以为没注册成功 → 再点「登录」→ 命中「留住本机」分支 → 界面变成空列表 → 桌宠记的那条彻底消失。
- 修：与 `handleLogin` 对齐；「用户名已存在」时提示走登录。

**24. 两台设备先后编辑时整份覆盖（无条件 upsert）**
- 协议是「整包密文、最后写入者赢」：上传是整个 `collectAppData()` 加密覆盖（无版本前置条件），`worker/src/index.js:468-480` 是无条件 `ON CONFLICT DO UPDATE`，拉取是整份替换。
- 没有条目级合并、没有删除标记、没有冲突提示 → 两边都改时**必然有一边被整份盖掉**。

## 六、安全 / 维护（6 条）

**25. `/api/chat`、`/api/fallback-log`、`/api/pet-log` 无服务端限流**（证伪员由「高」降「中」）
- `worker/src/index.js:482-521 / 523-540 / 543-560` 只有 `requireAuth` + trim，无任何次数/频率闸；注册只需用户名≥3 + 密码≥6，脚本可批量造假注册。
- 后果：可拿它当免费 LLM 网关刷 DeepSeek 余额、无限灌 D1 行 → 影响**所有用户**的可用性（与 DDoS 同后果），账单由项目主承担。
- 证伪员修正一处措辞：服务端 `:493-496` 会把所有非 assistant 角色强制降级为 user，所以**不是「system 可注入」**，而是「没有任何服务端固化的行为约束」。
- 成本前提：`DEEPSEEK_KEY` 已配置（没配则直接返回、零成本）。
- 修：① 按 userId 限速（如每账号每分钟 10 次，超限 429）② 服务端拼固定 system 前缀，忽略客户端的 system ③ 两个 log 接口加单账号每日行数上限 + 定期清理。

**26. 登录会话 Cookie 缺 `Secure`**（证伪员由「中」降「低」）
- `worker/src/index.js:43` 的 `setSessionCookie` 拼的是 `HttpOnly; SameSite=Lax; Path=/; Max-Age=`，确实漏了 `Secure`（清除版 `:50` 同）。
- 证伪员：站点在 Cloudflare 上、默认跳 https，「公共 Wi-Fi 抓包即得」是**夸大**了；真实利用需要 on-path 攻击者做 TLS 剥离。**缺这个 flag 是真缺陷、修起来极便宜**（收益为零、风险不为零）。
- 修：加 `Secure`；可在入口对非 https 的写操作直接 400。

**27. Electron 停在 `^33.4.11`（已 EOL）+ 主窗口远程加载线上页面**
- `desktop/package.json:18` 的 caret 范围**永远升不到 34+**；Electron 33 对应 Chromium 130，官方只维护最近 3 个大版本 → **不再收到任何安全修复**。
- `desktop/main.js:86` 主窗口 `loadURL("https://todo.aebuiyke.xyz")` → 所有已安装用户都在用不再打补丁的内核渲染线上内容。
- 证伪员维持「中」：属维护性风险、用户零感知，「该修但不紧急」。
- 修：升级到当前稳定大版本（先定好回归清单：双窗口 / 透明桌宠 / 托盘 / 自动更新）。

**28-30（其余安全/维护项）**：`hashAccountId` 相关、打包体积、`saveViewPrefs` 无 try/catch 导致错误页每次重载必再触发（用户卡在错误页出不来）、网页版双标签页吉祥物聊天记录互相覆盖等。

## 七、功能优化建议（调研了 20+ 来源后的排名）

来源包括：TickTick 官方帮助中心 77 篇（含 2026 新 AI 功能）、Todoist 中文文档 + Ramble、微软 To Do、Things 3（含 2026-08 的 3.23）、Any.do Moment、ChatGPT Tasks、多款桌宠（Desktop Mate / Shimeji / Bongo Cat / DesktopPet-Miao）、番茄ToDo / 时光序 / 小日常、Super Productivity / Vikunja 开源项目、爱范儿《桌宠四十年》等。

### 🎯 如果只做 5 件，就做这 5 件

**① 让轻宜「挑事」—— 每天帮你挑 3 件今天搞定的**
- 痛点：TickTick 8.0 把它做成头部新功能的理由很实在 ——「有一长串任务，但不知道从哪开始」，一打开就是压力。
- 抄法：早上主动搭话里加一句「要不要我帮你挑 3 件今天搞定的？」→ 从**逾期最久 + 被推迟次数最多 + 今天到期**里选 3 条。
- 为什么排第一：**你们的数据已经全在本地了**（任务、完成时间、改期记录），只是没人「看」。TickTick 的规则是明文的、纯本地、**零 AI 成本**。
- 难度：低（半天到一天）·**不冲突**（反而减少用户打开主界面的次数）。

**② 给完成任务一个「回响」**
- 跨产品看，没有一个待办软件死于「功能不够」，全都死于「用户不回来」。你们自己的调研笔记写过：「问题不是功能少，是把已有功能做得太安静。」
- 三条都是几行代码级别：**今日进度环**（完成 1/5 → 3/5，自己会动）；**连续天数**（连续 3 天清空今日 → 轻宜换一句更亲的台词，不做完整成就系统）；**完成瞬间的桌宠反应**（勾掉重要任务时它蹦一下）。
- 难度：低 ·纯加法、不加界面。

**③ 长按桌宠说话（语音入口）**
- 2026 年 Todoist 和 TickTick **同时押注**的方向。Todoist Ramble 官方原话：「你的思维比手指快，用嘴比打字快 4 倍」。场景：会议刚散、地铁上、专注时被打断。
- 你们的天然优势：**桌宠就蹲在屏幕上**，不用切窗口找输入框。
- 最小版做法：长按 → 说话 → 松手 → 复用现有 `nlp.ts` 抽时间 → 存成待办/备忘。**兜底必须有**：识别失败就原样存成备忘让用户改，绝不丢东西。
- ⚠️ 分水岭：加不加「实际上，我的意思是……」这种编辑语句 —— 没有它，说错一句就废一条。

**④ 「今晚 10 点帮我过一遍今天」（收尾仪式）**
- 抄 Sunsama 的 shutdown ritual + 桌宠形态。TickTick 做了年终总结，Sunsama 把「每天收尾」做成了产品灵魂。
- 桌宠独家：收尾不该是点开某个页面，**应该是晚上 10 点轻宜自己走过来问你**：「今天做完 3 件，还剩 2 件没动（其中 1 件拖了 5 天了）。要不要挪一挪？还是明天弄？」→ 回「明天弄」→ 一句话批量顺延。
- 难度：低-中 · 和 #1 共用同一套「拖太久」判定逻辑。

**⑤ 专注计时绑在桌宠的**物理形态**上**
- 番茄ToDo 做到 7000 万用户就是为了「开始了但坚持不住」。
- 桌宠独有玩法：专注时**桌宠趴下睡觉、头顶出现倒计时环** → 用户用余光就知道自己在专注，不需要看任何界面；25 分钟到了它醒来 →「休息 5 分钟吧」。
- 顺带一招（护眼宝）：到点让宠物跳出来、**点一下就消失**，不弹系统弹窗、不强锁屏。
- 难度：低（复用已有 `reminder.ts` + 桌宠动画）。

### 🔧 其余值得借鉴（按性价比）

| 功能 | 来自 | 难度 |
|---|---|---|
| **持续性提醒**（重要的事提醒到你处理为止）—— 但**必须限制为「用户手动勾选重要」的任务**，否则变骚扰 | TickTick Constant Reminder | 低 |
| **拖太久自动「抖出来」**：改期 5 次 → 轻宜主动问「这事拖 5 次了，是不是其实不想做？」 | TickTick 建议任务 | 低 |
| **桌面浮动小窗**：今日 3 件事钉在桌面角落，不打开程序就能看到（**别做成第二套完整界面**） | 用户反思文 + Super Productivity | 中 |
| **重复任务「这次例外」**：每周一的会这周改周二，**只变这一次**，规则不动 | Things 3（2026-08 的 3.23 专门修这个） | 低-中（已有 `repeat.ts`） |
| **提前完成循环任务**：周六浇花周五就浇了 → 直接打勾、自动生成下一次 | Things 3.23 | 低 |
| **历史「那天做了什么」**：日历往回翻看历史完成 | Things Logbook / TickTick Year View | 低（日历视图已有基础） |
| **倒数日/纪念日** —— 要**合并进「目标」**，不要新开板块 | TickTick Countdown / 时光序 | 低 |
| **托盘/全局快捷键速记**（Ctrl+Shift+Space 唤出） | 各类 PC 待办 | 低 |

### ❌ 看起来酷但别做

1. **完整习惯打卡体系**（小日常/TickTick Habit）—— 小日常能活是因为**只做打卡**；加进轻待办 = 在待办之外再造一个「每天要交作业」的负担。用「循环任务 + 连续天数」覆盖 80% 即可。
2. **番茄 ToDo 的锁机/白名单/自习室** —— 那是给自制力困难的中学生做的**对抗性产品**，价值在「强制」，跟「轻」完全相反；两人团队维护这个（Windows 白名单、杀进程、防绕过）是灾难。
3. **看板 / 时间线 / 艾森豪威尔矩阵 / 自定义过滤器** —— 加一个视图 = 加一套要多端同步、要维护、要翻译的状态；非程序员用户 95% 时间只在「今日」页。
4. **完整成就/等级/徽章系统** —— 做全量 = 做一套游戏系统；压成「连续天数 + 换台词」就对了。
5. **团队协作 / 共享清单** —— 加协作 = 加权限、加实时、加冲突解决，赛道直接变了。
6. **别做「AI 自动帮你操作电脑/读文件」** —— 安全隐患 + 巨大复杂度；用户是普通人。轻宜的气质应该是「陪你、提醒你」，不是「替你干活」。
7. **别做 Live2D 升级** —— 那是另一个技术栈（Cubism 4 授权 + PIXI.js）；你们现有的 bloub 引擎（会形变、有物理）已经足够「活」。

### 🐾 桌宠独有、竞品做不了的

- **「我看着你」——状态外化在屏幕上**：专注时趴着睡、你新建任务时它动一下、报错时它抖一下。用户不用打开任何界面，**用余光就知道状态** —— 这是「屏幕边缘的一只活物」独有的信息通道，手机 App 永远做不到。
- **「它记得你」——记忆要具体**：不是「你想聊点什么」，而是「你上礼拜那条『交房租』还没打勾哦」。⚠️ 只引用**具体任务和时间**，绝不引用隐私内容（既是产品问题也是安全问题）。
- **「拖太久了，我帮你面对」** —— **这个别人全都没做过**：一条任务被推迟 5 次后，轻宜不再安静，它把那条任务「叼」到屏幕上，用户点「行，现在做」或「算了，删掉」。**把抽象的拖延变成一个可以跟宠物互动解决的动作。** TickTick 只能冷冷地列一个列表，而你们能做成事件。
- **「不用等你说」——主动搭话的节奏是护城河**：现有 `morningNudge` / `idleChatter` / `lullChatter` 继续扩（任务完成时、收尾时、「我想到一件事」时）。⚠️ **底线：每次搭话都必须有信息量**，参考 Clippy 之死 —— 「能给出具体任务/时间就说话，给不出就闭嘴」。
- **亲密度靠行为驱动**（低成本高粘性）：好感度分档改变台词风格（生疏 → 普通 → 亲密）。⚠️ **别做喂食/洗澡/生病那套**，用户不是来养电子鸡的；改成完成任务涨亲密度、长期不互动降一点、解锁专属动作。localStorage 就能做。
- **语音识别的「拆多条」**：一口气说 5 件事 → 拆成多条任务（会议刚散、睡前清空大脑的场景）。

### 📌 三条落地纪律

1. **所有建议里的「AI 部分」都必须先本地兜底** —— 挑事、拖太久、收尾复盘全能用本地规则跑，AI 只负责「说得像人话」。别让新功能依赖网络。
2. **每加一个功能，先问「用户不打开程序时它存在吗」** —— 桌宠类功能都是「不需要打开」，这才是差异化。
3. 参考：**桌面宠物档案、语音入口、收尾仪式**这三样，竞品结构上就做不了。
