### F. 该拒绝的（越界）
| 用户可能说 | 轻宜的反应 |
|---|---|
| 帮我写代码 / 用c++写链表 / 翻译这段 / 算道数学题 / 推荐电影 / 今天天气怎样 | 礼貌拒绝 + 引导回待办（**不发给 AI，省 token**） |

### G. 兜底（真听不懂时）
**核心原则（调研最佳实践）：永远不说"听不懂"，改成"猜 + 确认"。**
| 情况 | 轻宜的反应 |
|---|---|
| 像"一件小事" | "你是想让我记下「X」吗？回'记下来'我就建" |
| 含时间词但没识别出动作 | "你是想安排「X」这件事吗？" |
| 含"怎么/如何" | "这是在问我怎么做吗？我擅长…" |
| 完全不懂 | 能力菜单（带具体例子）+ **带上用户原话**（显得在听） |

## 二、防幻觉三道闸门（重要，别再犯）

AI 会"假装做了没做的事"（如说"已帮你删除"其实没删）。三道防线：

1. **本地能办的绝不问 AI** —— 建/删/改/完成/查/记 全是本地规则
2. **本地已下结论的绝不问 AI**（`localOnly`）—— AI 没机会编
3. **多候选记住了**（`choices`）—— 用户选的时候直接命中，不绕 AI
4. **多轮选中链路**（`pendingChoices`）—— 用户回"开会"能对上候选

---

## 三、意图优先级（代码里的判定顺序，别乱动）

```
越界拦截 → 问候/礼貌 → 删除 → 完成/取消完成 → 更新 → 查询 → 记备忘
→ 情绪 → 建任务 → 兜底(猜+确认) → (AI 只处理剩余纯闲聊)
```

**为什么这个顺序**：误判代价高的（删除）优先；"完成"要排除问句（否则"还有多少没完成的"会被答非所问）。

## 五、已知边界（诚实告知，别让用户以为它万能）

- **纯前端 SPA**：网页关了就没有后台提醒（不是 bug，是浏览器限制）
- **裸小时不做下午推断**："四点"= 04:00（要下午请说"下午四点"）—— 因为自动推断会把"8点"错成20:00
- **跨会话记忆**：聊天记录存本机（最近60条/空间），换设备不同步（隐私优先）
- **AI 回复**：DeepSeek 只用于纯闲聊/情感；所有实际动作用本地规则，防幻觉
