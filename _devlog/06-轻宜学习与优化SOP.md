# 轻宜 · 学习与优化 SOP（让助手越用越聪明）

> 这份是**"怎么让轻宜持续变聪明"的操作手册**。核心是形成一个闭环，而不是等用户报 bug 才修。
> 配套：`05-轻宜对话能力清单.md`（会什么）、`tests/`（169 条自动测试）、`lib/mascotLearn.ts`（记录机制）。

---

## 一、学习闭环（五步，缺一不可）

```
① 记录  →  ② 分析  →  ③ 变规则/测试  →  ④ 上线  →  ⑤ 观察是否减少  ↺
```

| 步 | 做什么 | 工具/位置 |
|---|---|---|
| **① 记录** | 用户说了一句轻宜"没答好"（兜底/没识别）→ **自动记本机** | `lib/mascotLearn.ts`，触发点：`mascotBrain` 兜底回复带 `fallback:true` |
| **② 分析** | 看**高频**没答好的句子（按次数排序），优先修出现最多的 | 对话面板 ⚙ → "学习日志" → 复制 |
| **③ 变规则** | 把高频句归纳成**规则**（改 `mascotBrain.ts`）**并写一条测试**（加进 `tests/`） | 测试是"防复发"的锁 |
| **④ 上线** | `npm test` 全过 → `npm run build` → `wrangler deploy` | 三道关 |
| **⑤ 观察** | 看学习日志里这句话还出不出现；不出现=修好了 | 日志计数归零 |

**关键纪律**：**每修一个 bug，必须同时加一条测试**——否则同样的错会再犯（我们已犯过多次）。

---

## 二、日常该做的（不等用户报 bug）

### 每周（20 分钟）
1. 打开 ⚙ → 学习日志 → **复制**
2. 看 Top 10 高频没答好的句子
3. 挑 3 条归纳成规则 + 写测试
4. 上线

### 每次加功能后
1. 在 `05-对话能力清单.md` **登记**这个能力（用户说什么 → 做什么）
2. 在 `tests/` 加 3~5 条测试（正常/边界/易混）
3. 跑全量测试

### 每次上线前（**硬性**，用户明确要求）
```
npx tsc --noEmit     # 类型
npm test             # 169+ 条测试全过
npm run build        # 能构建
```
**三道全过才部署**，否则不上。

## 三、测试该怎么写（覆盖面方法论）

按**六个角度**覆盖同一能力（照我们已用的方法）：

| 角度 | 例子 | 目的 |
|---|---|---|
| **标准说法** | "明天下午3点开会" | 正常能用 |
| **口语/省略** | "明早交材料" / "买菜" | 真人不会说标准话 |
| **同义多说法** | "还有多少没做"/"未完成的有几个"/"还剩几件" | 一句话有很多说法 |
| **易混/歧义** | "完成了开会"(操作) vs "完成了几个"(查询) | 别答非所问 |
| **边界** | 空输入/超长/emoji/乱码 | 别崩 |
| **该拒绝** | "帮我写代码" | 边界内守规矩 |

**方法**：一条能力，先写 5~10 种说法，跑测试，**错的修掉、对的留作回归**。

## 四、评测集来源（越用越全）

1. **用户实际说过的话**（学习日志）——最有价值，真实
2. **同类产品会怎么问**（调研清单，见 `03-竞品调研笔记.md`）
3. **自己模拟**（"如果我是用户，我会怎么问这个功能"）
4. **线上 bug 复现句**（每次修完必加）

> 目标：**测试集 = 真实的用户问题库**，而不是拍脑袋想出来的。

## 七、全站汇总（v3.9 新增）—— 让所有用户的坑汇总到一处

### 为什么需要
本机学习只帮"你自己"：你训练得再好，新用户一问还是遇到同样的坑。所以必须**汇总到服务端**，统一优化一次、所有人受益。

### 怎么工作的
```
用户A没说好 ─┐
用户B没说好 ─┼→ /api/fallback-log → D1 mascot_fallback 表 → 按句子聚合
用户C没说好 ─┘                                              ↓
                                       GET /api/fallback-summary 看 Top 高频
```

### 🔑 你怎么查全站汇总（就一条命令）

**浏览器直接打开这个网址**（把 key 换成你设的）：

```
https://todo.aebuiyke.xyz/api/fallback-summary?key=qhjy2026
```

返回示例：
```json
{"ok":true,"total":2,"items":[
  {"text":"帮我看看那个啥","cnt":5,"users":3,"last_ts":1788000001000}
]}
```
- `cnt` = 这句话被说过几次（越多越该优先修）
- `users` = 多少个**不同用户**遇到（说明是个普遍问题）
- `text` = 用户原话

> 想改页码/条数：加 `&limit=100`

### 隐私边界（写清楚，别越线）
| 上报 | ✅ 只上报"没答好的那句话"（截断 120 字） |
|---|---|
| **绝不上报** | ❌ 任务标题 ❌ 备忘内容 ❌ 账号名 ❌ 其他对话 |
| 用户可关 | 设置里"帮助改进"开关，关掉就不上报 |
| 账号脱敏 | 存的是 hash 不是用户名 |

### 用它的日常流程
1. 每隔几天打开一次上面的网址
2. 看 `cnt` 最高、`users` 最多的几句
3. 这几句就是**最该优先修的**——修完加测试、上线
4. 下次再看，这几句应该消失或大减
