### G. 对抗测试发现（2026-09-04，独立挑刺测试员实测 130 句）

**高危（会丢任务/建反）**
| 问题 | 根因 | 解法 |
|---|---|---|
| "周报写完了/开完会了"→被建成任务 | 完成词表缺"写完了/开完"，且标题匹配是同序包含（"周报写完"≠"写周报"） | 扩完成词表 + **matchTasks 宽松匹配**（双向包含+去助词） |
| "烦死了明天还要开会"→任务被情绪吞 | tryFeeling 排在 tryAddTask 前且命中即截胡 | 检测到"时间+事务"时先建任务，情绪后置 |
| "帮我买牛奶/取快递/发周报"→被拒答"帮不上忙" | isOffTopic 的 SERVICE_REQ 白名单太窄 | 加 TASK_ACTION(动词)+TASK_NOUN(事务名词) 白名单 |
| "完成开会。"（带句号）→识别失败 | 关键词剥离不处理标点 | tryDelete/tryComplete 先 `去标点` |

**中危**
| 问题 | 解法 |
|---|---|
| "下下周一"算成下周一（早一周） | nlp 支持 `下下` 前缀 |
| "两个小时后/半小时后"不解析 | nlp 加相对时间规则（含"半"、"一会儿"） |
| "今晚12点"错成中午12点 | 明确"今晚/夜里+12点"→23:59 |
| 候选列表不带日期，同名任务没法选 | fmtCand 带日期（如"1.开会（09-23 09:00）"） |
| "取消明天的会议"被建成任务 | tryAddTask 开头拦"取消/不开了" |
| "记到备忘录："空内容被记成"：" | tryAddMemo 校验有实义 |
| "记录：xxx"被啃成"录：xxx" | stripHelp 加"记录/记事"外壳 |
| "今天几号/星期几"被建任务 | isQuestion 加"几号/星期几/周几" |

**低危**
| 问题 | 解法 |
|---|---|
| "下个月5号"算成本月5号 | nlp 优先"下个月X号"；X号规则不覆盖已算日期 |
| 疑问句被引导记垃圾（"现在几点"） | looksLikeThing 排除疑问词 |
| 天气闲聊被拦（设计里想放行AI） | 从 OFF_TOPIC 移除天气 |
| "明天（明天）"重复文案 | 修正 query 模板 |
| 节日词（国庆/过年）不认 | 待办（未修，低优先） |
| "记账/记事"被反问 | 按备忘处理 |
| 政治/报复类未拦 | OFF_TOPIC 加词 |

**通用教训（写进纪律）**：
- **用户说法 ≠ 任务名**（"周报写完了" vs "写周报"）→ 匹配要**宽松**（双向/去助词）
- **标点/语气词**必须预处理，中文用户爱带句号
- **顺序决定成败**：情绪 vs 建任务、完成 vs 建任务，都要按"误判代价"排

## 二·五、桌面版 Mac 兼容（v3.9.21，2026-09-27）

> **背景**：桌面版自始至终**只在 Windows 上开发/打包/验证**，Mac 版配置写好了却没人检查过
> "Mac 上跑起来会怎样"。做 Mac 包之前逐条排查 main.js，发现**三个一装就中的坑** ——
> 都不是小毛病，是"装了就没法用 / 整台电脑点不动"级别。
> **教训：凡是 Windows-only 写法的代码，加平台分支前先当成 bug 看待。**

| # | 问题 | 根因 | 解法 | 测试 |
|---|---|---|---|---|
| M1 | **Mac 上整台电脑点不动**（致命）| 第一行 `app.disableHardwareAcceleration()` 是为修 Windows 透明窗黑底，但 Electron 官方文档写明：**Mac 上关硬件加速时 `setIgnoreMouseEvents` 直接不生效**。桌宠窗是**铺满整屏的透明置顶窗**，穿透一失效 → 一个看不见的全屏窗罩住屏幕 | 加平台判断，**只在非 darwin 上关** | `mac-compat.test.ts` 断言该调用必须被 `platform !== "darwin"` 包住 |
| M2 | **拖到一半拖不动**（Mac 上必然踩中）| "鼠标键按着就绝不切回穿透"这条命脉，Windows 上靠 `startMouseButtonWatcher()`（常驻 PowerShell 读 `GetAsyncKeyState`）兜底；**Mac 上没有**（函数开头就 `platform !== "win32"` 返回）。而页面上报在 capture 丢失后收不到任何事件 → 状态卡死 | `startMouseHeldWatch` 加**第二重独立监听**（`mousemove`/`mouseup`，走不同派发链）互相纠偏 | 断言监听挂在 `window` 上（挂元素上会随 capture 失效）且读 `e.buttons` |
| M3 | **一进全屏宠物就"消失"** | Mac 的"空间"概念：全屏 App 是独立空间，窗口默认不跟过去。`setVisibleOnAllWorkspaces(true)` 在 Mac 上**默认不覆盖全屏空间**，必须显式传 `{ visibleOnFullScreen: true }` | darwin 分支传该选项（外加 `skipTransformProcessType` 防 Dock 图标闪烁）| 断言至少一处调用带 `visibleOnFullScreen` |
| M4 | 菜单栏/程序名显示成 **"Electron"** | macOS 用 Info.plist 的 `CFBundleName` 给应用命名，未签名构建里默认是 "Electron" | `app.setName("轻待办")` + `extendInfo` 补 `CFBundleName`/`CFBundleDisplayName` | 打包配置校验 |
| M5 | 常驻桌宠在 Dock 里占一格 | 桌宠是常驻型，不该占 Dock | `app.dock.hide()`（Mac 专属，whenReady 后调）| — |

**另外两条 Mac 上容易踩的（本次已确认没问题，留档备查）**：
- 坐标换算：`getCursorScreenPoint()` 返回的就是 DIP，**不要再除 scaleFactor** —— Mac 视网膜屏 scaleFactor=2，一旦除了偏移直接翻倍
- 阴影：`hasShadow: false` —— Mac 上透明窗若带阴影，会在桌宠周围留一圈淡淡的方框

## 二·六、构建 / 文件名编码类（2026-09-27）

> **背景**：GitHub Actions 的 windows-latest 上 `actions/checkout@v4` 报
> `error: invalid path '_devlog/"00-\351\234\200...md"'`；同一份代码 macos-latest 能过。
> 根因**不在文件名、也不在本地仓库**，而在"推代码的工具"：
> `tools/push-via-api.mjs` 用 `git ls-tree <sha>`（**没加 `-z`**）解析树 → git 按
> `core.quotepath` 把中文名渲染成**带引号的八进制转义**（`"_devlog/00-\351\234\200...md"`）
> → 脚本把这段"给人看的渲染文本"当**字面路径** POST 给 GitHub 树接口 →
> 远端树里存出"名字真的带 `"` 和 `\` 的文件"。
> Windows 的 NTFS 不允许 `" \ : * ? < > |` → checkout 直接失败；macOS 全允许 → 没事。
> **本地 git 库从头到尾都是对的**（UTF-8 原样字节），坏的只有"被接口推上去的"那串提交。

| 问题现象 | 根因 | 解法 |
|---|---|---|
| windows-latest 报 `invalid path '_devlog/"00-\351...md"'` | 推送脚本 `ls-tree` 未加 `-z`，把 quotepath 转义渲染当字面路径上传 | ①脚本改 `ls-tree -z` + NUL 解析 ②上传前拦截含 `" \` 或控制符的路径（坏名当场退出）③远端坏分支/标签**强推对齐**到本地好提交 |
| 本地 `git ls-tree` 显示 `"_devlog/00-\351..."`，以为仓库坏了 | 只是 `core.quotepath`（默认 true）的**显示转义**，不是存储内容（用 `od -c` 可见原始 UTF-8 字节） | `git config core.quotepath false`；判断"真坏假坏"必须看字节（`od -c` / `ls-tree -z`），别信默认渲染 |

**纪律（踩坑换来的）**：
- **脚本解析 git 输出 → 一律加 `-z`**（NUL 分隔、原样字节）。`git ls-tree` / `ls-files` / `status` 的默认输出是**给人看的**（quotepath 转义），不是给程序解析的
- **跨平台文件名**：macOS 允许 `" \ :` 等字符，Windows 不允许 → "Mac 上没事"不等于"没事"，涉及文件名要在 Windows 上验一遍 checkout
- 排查顺序：先 `od -c` 看**字节**（区分"真坏"还是"显示转义"）→ 再定位"谁写进去的"（本地 git 还是接口脚本）

## 二·七、安装包分发与国内下载加速（v3.9.21，2026-09-27）

> **背景**：Mac 包做出来了，但**下不动** —— GitHub 国内直连实测 **33KB/s**，
> 91MB 要下 45 分钟（还随时可能断）。用户拿不到安装包 = 这个版本等于没发布。
> **教训：发版链路要一路测到"用户真的能把包装到他电脑上"为止，打包成功只是中点。**

| # | 问题现象 | 根因 | 解法 |
|---|---|---|---|
| D1 | 新增的 `/mirror/*` 路由不生效，任何路径都返回 `200` + 一段 HTML | `wrangler.toml` 的 `run_worker_first` 只列了 `/api/*` 和 `/dl/*`，新路由没登记 → 请求直接落进 SPA 兜底（不存在的路径统统回落 `index.html`）| `run_worker_first` 补上 `/mirror/*`。**新增任何 Worker 路由都要同步这份清单** |
| D2 | 镜像返回的中文报错是乱码 | Cloudflare 对未声明编码的 `Response` 按 latin-1 处理 | 纯文本响应必须显式 `content-type: text/plain; charset=utf-8` |
| D3 | Windows 自动更新不触发 | 旧的 `latest.yml` 是发布脚本**手动生成**的，GitHub Actions 里 electron-builder **根本没跑**（workflow 不执行 `npm run dist`）→ 新版没有 yml。且 workflow 的 `upload-artifact` 只收 `*.exe`/`*.blockmap`，**漏了 `*.yml`** | 本地按格式生成 `latest.yml`（sha512 用脚本算，别手打）连同 `.blockmap` 一起传 R2；**workflow 路径待补 `desktop/release/*.yml`** |
| D4 | 下载页长期指着 v3.9.4 的旧包 | 配置漂移：代码在走、`src/lib/downloads.ts` 没跟，且**没有任何地方会报错** | 新增第 19 科测试，把 `desktop/package.json` ↔ `downloads.ts` 的版本号、链接文件名、域名（必须自家域名）三者钉死 |

**实测速度对比（同一台机器、同一时段）**：

| 通道 | 速度 | 91MB 耗时 |
|---|---|---|
| GitHub Releases 直连 | ~33 KB/s | ~45 分钟 |
| 经 Worker `/mirror/*` 中转 | ~1.6 MB/s | ~57 秒 |
| R2 `/dl/*` 直连（最终方案） | ~3.0 MB/s | ~30 秒 |

**安全设计（`/mirror/*` 不能省的三道闸）**：
1. **仓库白名单**（`MIRROR_ALLOWED_REPOS`）—— 否则这个域名就成了"任何人可用的免费代理"
2. **只允许 `releases/download/` 子路径** —— 不给它代理仓库其它内容的能力
3. **逐段校验路径**，拒绝 `..`/空段 —— 防穿越

**顺带确认的**：Cloudflare Worker 的 `fetch` **自动解压上游 gzip**（实测透传安装包字节数
与源文件完全一致：`95399711`），所以代理二进制文件不需要额外处理编码。

## 二·八、桌面版双窗口数据互抹（v3.9.22，2026-09-27）

> **用户原话**：「明天要跟进vivo锁机事项」→ 轻宜回「好，我帮你记下了：\n「要跟进vivo锁机事项」\n⏰ 2026-09-28」
> → 用户去待办里找 → **没有** → 「他说给我添加了，问题待办里面根本没有找到」
>
> 这是**幻觉类里最伤人的一种**：不是它编了话，是它**真的做了**、话是诚实的，
> 数据却被另一个窗口悄悄抹掉了 —— 用户看到的就是"它在骗我"。
> **教训：报"已完成"之前，先确认那条数据真的存住、且没有别人在后面抹它。**

### 排查过程（结论先行：大脑没错，错在同步）

| 步骤 | 做法 | 结果 |
|---|---|---|
| 1 | 复现原话跑 `answer()` | 确实吐 `addTask` + 那段一模一样的回话 → **大脑是好的** |
| 2 | 读用户机器上真实的 `lighttodo:work:v1` | 41 条任务，**没有这条**，最近一条建于 9/22 → 确实没存住 |
| 3 | 查 `mascot_fallback` 表 | 事发时间 16:34~16:35，两条兜底记录 |
| 4 | 静态追 `answer → runAction → onAddTask → addTask → setWorkTasks` | **每一环都对**，桌宠窗口确实写盘了 |
| 5 | 看主窗口 | **它每 30 秒 / 每次窗口获得焦点，就把服务器旧数据整份替换本地并回写** |

### 根因（三件事叠在一起才出事）

1. **两个窗口共用一份 localStorage**（`partition: persist:lighttodo`）：
   ① 主窗口（完整网页界面）② 桌宠窗口（常驻桌面那只）。
2. 主窗口的任务列表在**内存**里，只在"自己"改动时才更新；
   它的防覆盖时间戳 `lastLocalEdit` 也**只有主窗口自己会赋值** —— **看不见桌宠的写入**。
3. 于是每 30 秒的拉取（`applyAppData`）都会把桌宠刚记的那条当成"多余的本地数据"抹掉。

**→ 桌宠记的待办，存活最多 30 秒。**
**→ 更糟的是：用户去主窗口找它，这个"点一下窗口"的动作正好触发拉取 —— 所以永远找不到。**

### 解法

| # | 改动 | 文件 |
|---|---|---|
| 1 | **写盘即"登记"水位**：本窗口写一次，就记一个时间戳（`bumpLocalRevision`） | `lib/syncLock.ts`（新） |
| 2 | **水位包含桌宠写的**：`localWatermark()` 从**磁盘**读任务/备忘的 `updatedAt` 最大值 —— 磁盘是两个窗口共用的，所以桌宠写的自然在内 | `App.tsx` |
| 3 | **判据换成"谁更新"**：拉取/恢复时 `本地水位 > 服务端水位` 就拒绝覆盖（原来只认"本窗口有没有编辑过"） | `App.tsx` |
| 4 | **跨窗口互听**：主窗口也订阅 `storage` 事件，另一个窗口一改立刻重读 | `App.tsx` / `DesktopPetApp.tsx` |
| 5 | **没变就不写**：内容与原值相同直接返回，防两个窗口把对方的新数据写回去、无限对写 | `tasks.ts` / `memos.ts` |
| 6 | **`normalizeTask` 保留 `updatedAt`**：原来它会刷成 `Date.now()`，等于"读一下就把水位抬到'现在'"，会让水位判据彻底失效 | `tasks.ts` |

### 🔴 修的时候差点弄坏的两件事（都很隐蔽）

| 陷阱 | 后果 | 怎么避的 |
|---|---|---|
| `collectAppData()` 每次把信封 `updatedAt` 刷成"现在" | 拿它当水位 → **本机永远显得比服务器新 → 服务器数据再也进不来**（多端同步静默失效，最难发现的那种） | `dataWatermark()` **只看条目自己的 `updatedAt`**，只有在"两边一条数据都没有"时才退回用信封时间 |
| 主窗口挂载时会 `loadTasks()` 再原样 `saveTasks()` 一次 | 这次"什么都没改的回写"会**把水位顶到"现在"** → 同样是多端同步静默失效 | `saveTasks` 首次写盘时拿**磁盘现状**当基准：内容一样就**不登记**水位 |

### 🔴🔴 但是第一版修完**还是没好** —— 真事故路径在"登录那一刻"

上面六条做完，用真实 Electron 双窗口跑，**原始场景依然复现**。又追了一轮才挖到底：

> 用户的**主窗口会话过期了**（`lighttodo:account:v1` 不在），所以它停在**登录页**。
> 用户是在**桌宠**里记的待办 —— 而登录那一刻：
> `handleLogin()` 开头 `resetAllLocalData()` 清空 state
> → 持久化 effect `useEffect(() => saveTasks("work", workTasks), [workTasks])` **下一帧就把 `[]` 写进磁盘**
> → 等于在 `await` 解密服务器数据的那段时间里，把桌宠记的那条**连同它自己的水位痕迹一起从磁盘删掉了**。
> 等守卫回过头想 `loadTasks("work")` 读回来，读到的已经是被自己人抹干净的空列表 —— **判据形同虚设。**

**这是本次最隐蔽的一处**：光"记住水位"没用，必须**根本不让这次空写落盘**。

| # | 补的改动 | 文件 |
|---|---|---|
| 7 | **认证期间落盘闸门** `beginAuthTransition()/endAuthTransition()`：登录/注册/恢复会话全程，`saveTasks`/`saveWorkMemos` 一律不写盘 | `lib/syncLock.ts`（新） |
| 8 | 闸门必须在**第一次 `await` 之前**开：`loginAccount()` 也是网络请求，等它回来空写早落下了 | `App.tsx` |
| 9 | **闸门必须在更新 `lastWritten` 之前返回** —— 否则被拦下的空写被记成"已写过"，关闸后真正的写反而被去重逻辑当成重复而跳过，磁盘永远停在旧值 | `tasks.ts` / `memos.ts` |
| 10 | **登录判据用"清空前"的快照**：磁盘此刻已被清空写过一轮，现读是错的 → `watermarkBeforeReset()` 存进局部变量带过去（**不要用模块级全局**，会被 register/logout 之间的陈旧值污染） | `App.tsx` |
| 11 | **登出清零水位** `resetLocalRevision()`：登出=本机不该再有要保护的数据，否则登出引发的空写把水位顶到"现在"，重登同账号会被判成"本机更新"→ 留住一个空列表 | `App.tsx` / `syncLock.ts` |
| 12 | 开局变量要 `let` 且初值 `0`：`beforeView`/`afterView` 是循环依赖，写成 `const` 会踩 TDZ（`cannot access before initialization`） | `App.tsx` |

**三条真机路径已用真实 Electron 双窗口验证（不是单测，是真跑）：**
① 桌宠写 → **已登录**的主窗口立刻显示出来
② 主窗口停在**登录页**时桌宠写 → 重新登录后**仍在**
③ **全新设备**登录同一账号 → 仍能拿到服务器数据（多端同步没被这次修改破坏）

**教训（本条最值钱）：**
- **"清空界面残留"和"删用户数据"是两回事** —— `resetAllLocalData()` 的语义只是前者，
  但持久化 effect 分不清，于是把前者当后者执行了。
  **给"清空"配持久化 effect 时，必须问一句：这次写会不会落到磁盘上把用户的真数据删掉。**
- 光"记住水位"不够：**只要磁盘上的原始数据还有可能被自己人删掉，判据就不成立。**
- 第一版修完就以为好了 → 是**真机复现**把它否掉的。
  **这类"两个 effect 抢时序"的 bug，单测全绿也可能是坏的；必须端到端真跑。**

**教训：给"防覆盖判据"加水位时，必须同时确认"水位不会被读取动作自己抬高"。**
这两条如果不查，修完表面上好了，实际上多端同步悄悄废掉 —— 比原 bug 更难查。

### 验证（不是推的，是实跑的）

- 新建 Chromium partition 开两个窗口（模拟主窗口 + 桌宠窗口），**跑线上真实域名**：
  桌宠窗口写一条 → 主窗口**收到 storage 事件、立即读到那条**（`__n=1`）；
  再改一次内容 → 再收到（`__n=2`）→ 链路成立
- 第 20 科测试 16 条（`tests/cross-window-sync.test.ts`），含上面两个"反向保护"陷阱的断言

## 二·九、Mac 安装包"装了打不开"—— 两个芯片的包互相覆盖（v3.9.22，2026-09-27）

> **用户原话**：「苹果电脑还是不行，显示你无法打开应用程序清代版，因为这台mac不支持应用程序」
> 用户机器：**2018 款 Intel MacBook Pro**。

### 排查（拆开线上包验的，不是猜的）

| 步骤 | 做法 | 结果 |
|---|---|---|
| 1 | 下载线上 `/dl/light-todo-setup-3.9.21-mac.zip`，读主程序的 Mach-O 头 | magic `0xcffaedfe` + cputype `0x0100000c` → **arm64（Apple 芯片专用）** |
| 2 | 查 GitHub Release 的 assets | **只有一个 `mac.zip`（91MB）** —— 本该有 Intel + Apple 两份 |
| 3 | 翻 `desktop/package.json` 的 mac 配置 | `target.arch = [x64, arm64]` ✅ 两种都配了 |
| 4 | 看 `artifactName` | `light-todo-setup-${version}-mac.${ext}` —— **没带 `${arch}`** ❌ |

### 根因

`artifactName` 里没有芯片名 → electron-builder 按 `x64`、`arm64` **先后打了两个包，
但用了同一个文件名，后者把前者覆盖掉** → 磁盘上只剩一个 → 上传的也就只有一个。
而"活下来"的那个恰好是 arm64。

**Intel 机器上跑 arm64 包 = macOS 直接拒绝**，报「这台 Mac 不支持此应用程序」。

### 🔴 这类 bug 为什么难发现

**每一步都"成功"了** —— 构建成功、上传成功、下载成功、页面正常、按钮能点、
文件名看起来也完全正常。**没有任何一处会报错。**
只有用户在**特定芯片**的机器上装的时候才会发现，而且报的错用户完全看不懂
（"这台 Mac 不支持此应用程序"听起来像电脑太老了）。

**教训：一个构建产物如果有多个变体（架构/渠道/语言），文件名里必须能区分它们。**
只靠"打两个包"是不够的 —— 名字撞了，等于只打了一个。

### 解法

| # | 改动 | 文件 |
|---|---|---|
| 1 | `artifactName` 加 `${arch}`：`light-todo-setup-${version}-mac-${arch}.${ext}` | `desktop/package.json` |
| 2 | Mac 下载链接**拆成两个**（`macIntel` / `macApple`），不再共用一个 | `src/lib/downloads.ts` |
| 3 | 新增 `pickMacDownload(ua)` —— 下载页**按芯片自动挑**，用户不用懂这些 | `src/lib/downloads.ts` |
| 4 | Mac 卡片显示"已为你选好 Intel 芯片版 / Apple 芯片版" | `DownloadPage.tsx` |
| 5 | `release.sh` 从 GitHub Release 取回**两个** Mac 包一起传 R2，缺一个就中止 | `desktop/scripts/release.sh` |
| 6 | Release 说明写清"怎么知道自己是什么芯片" | `build-desktop.yml` |

### 🔴 挑芯片时差点写错的地方（已加测试锁死）

| 陷阱 | 若写错会怎样 |
|---|---|
| 拿 UA 里的 `Intel Mac OS X` 当判据 | 那是**历史遗留的固定串，Intel 和 Apple 芯片的 UA 里都有** → 把所有 Apple 芯片用户都判成 Intel |
| 判不出来时默认给 arm64 | **arm64 包在 Intel 机器上根本装不上**，而 Intel 包在 Apple 芯片上能跑（Rosetta 转译）→ **默认值必须偏 Intel 才安全**（安全性是不对称的） |

正确判据：UA 里有没有 `arm64`。

### 验证（二进制层面验的，不是看文件名）

- 重新构建后 Release 里**两个包都在**：`mac-x64.zip`（95.4MB）+ `mac-arm64.zip`（91.0MB）
- 把 `mac-x64.zip` 下下来读 Mach-O 头：cputype `0x01000007` → **x86_64（Intel）** ✅
- 第 19 科加 5 条断言：artifactName 必带 `${arch}`、两种架构都要打、下载页必须分流、
  判据不许用错串、默认值必须偏 Intel

### 🔴🔴 发布环节又踩两个坑（同一个脚本，都在"上传到 R2"这一步）

修完芯片问题、跑 `release.sh` 发版时，**脚本报成功、线上却 404**。两个独立的坑叠在一起：

**坑 1：`cd` 之后相对路径失效（脚本自身的老 bug，这次才炸）**

```
SETUP=release/light-todo-setup-3.9.22.exe     # ← 相对路径
...
cd "$PROJ/worker"                              # ← 换目录了
npx wrangler r2 object put ... --file="$SETUP" # ← 现在它相对 worker/ 找，找不到
```

报错是 `The file "release/light-todo-setup-3.9.20.exe" does not exist.` ——
而且 **wrangler 从第一个文件就失败退出**，所以三个包**一个都没传上去**（不是只少一个）。
> 有意思的是错误信息里的版本号是 3.9.20 不是 3.9.22 —— 因为 `$SETUP` 用的是**上一次**运行
> 残留的旧变量值。这种"错误信息里的东西对不上"的现象，本身就是路径串了的信号。
>
> **修**：`cd` 之前先把所有路径转成绝对路径，并且在 `cd` 前逐个 `[ -f ]` 检查存在性。

**坑 2：`wrangler r2 object put` 默认写进「本地模拟桶」，不是真桶** ⭐ 更隐蔽

wrangler 4.x 里 `r2 object put/get` 默认操作的是 `.wrangler/state` 下的**本地模拟 R2**。
它一样打印 `Upload complete.`，只在前面多一行 `Resource location: local`。
后果是一套完整的假象：

| 你以为 | 实际 |
|---|---|
| 上传成功（有 "Upload complete."） | 写进了本地磁盘的模拟桶 |
| 本地 `r2 object get` 能读出来，验证通过 ✅ | 读的是**同一个**本地模拟桶 |
| 线上下载页 404 ❌ | 真桶里根本没有这些文件 |

**判断真假的唯一铁证：输出里必须是 `Resource location: remote`。**
> ⚠️ 我一度以为"不能加 `--remote`，加了反而报 local" —— 那是被上面那句
> `Resource location: local` 误导了。实测：**不加 `--remote` 才是 local，加了才是 remote。**
> 当时基于错误推断在注释里写下的"不能加 --remote"是错的，已改正。

**修**：所有 `r2 object put` 加 `--remote`；发布后必须用 `curl` 打一次**真实下载链接**才算数。
顺手清掉了本地模拟桶里误传的 358MB。

### 发版检查清单（v3.9.22 起，每次发版照做）

1. `npx tsc --noEmit` + `npm test` + `npm run build` 全过
2. `bash desktop/scripts/release.sh` —— 输出里每个包都要有 `Resource location: remote`
3. **`curl` 打四个真实链接**（exe / mac-x64 / mac-arm64 / latest.yml），必须全 200
4. 部署网页（`wrangler deploy`）后用 `curl "https://todo.aebuiyke.xyz/?v=$RANDOM"` 确认
   引用的是**新**的 `index-*.js`（不带参数那次可能是边缘缓存，会看到旧包名）
5. 判断用户要不要重装：**桌面程序本身改了 → 要装新版**；只改了网页 → 刷新即可

### 🔴 修的时候踩的三个坑（都是"修完等于没修"的那种）

| 坑 | 现象 | 怎么发现的 / 怎么避的 |
|---|---|---|

## 二·十四、整站"发灰看不清"—— 强调色被当成文字色用了 47 处（v3.9.24，2026-09-28）

### 现象

一位 UI 调研（对比 GitHub 同类产品）的人说：**"主按钮看着糊"**。
一开始以为是"某个变量没定义"这种小毛病。

### 查下去发现是系统性的

拿真 WCAG 公式实测了所有配色对（**不是肉眼估**）：

| 用在哪 | 对比度 | 线 |
|---|---|---|
| 白字 + 强调色实底（**新建/保存/登录**等主按钮，12 处） | **2.87** 紫 / 2.95 青绿 | 4.5 |
| `color: var(--accent)` 当文字（**47 处**：导航选中、标签、日历"今天"…） | **2.87** 白底 / **2.37** 浅底 | 4.5 |
| `--accent-ink` 写在 `--accent-soft` 上（导航标、卡片图标） | **3.39** 紫 / 3.56 青绿 | 4.5 |
| `--text-3` 次要文字 | 2.58 | 4.5 |
| `--ok` 完成态绿 | 3.30 | 4.5 |
| `--accent-ink` 当**背景**（热力图最深一格） | **透明**（变量根本没定义） | — |

**根因一句话**：强调色 `#8B91E8` 是**刻意压过饱和度的浅色**（用户挑的就是这套），
它天生只能当**填充/背景**。可代码里既拿它当底色写白字、又拿它当文字色写在白底上 ——
两个方向都不及格。**不是某一处写错，是"这个色该怎么用"从来没定过规矩。**

### 修法：定 token 规矩，底色一个像素不动

```
--accent        只当填充色（背景块、进度条、点）
--accent-ink    同色系深色，所有"强调色文字"都用它
--on-accent     写在 --accent 实底上的字（不是白！）
--accent-hover  悬停加深一点点（8%）
```

**为什么不直接改底色？** 因为用户挑的就是这套低饱和色，"好看"的部分没问题，
问题在**上面写了什么**。改底色 = 改掉用户选的东西，属于越权。

### 🔴 三个值得记的点

**① 悬停色不能直接用 `--accent-ink`。**
第一版把 `:hover { background: var(--accent-ink) }` 当作"加深"，
但 ink 现在被压得很深（为了当文字色），压上去之后**底上的字反而掉到 3.4** ——
"越悬停越糊"。实测后改成 8% 的浅加深（`--accent-hover`），最低 3.98。

**② `--coral-ink` 和 `--accent-ink` 是两套东西，别顺手合并。**
`--coral-ink` 全项目**没有任何地方读**（考古遗留），`--accent-ink` 才有 5 处在用。
合并会误导后人，保持独立、各配注释。

**③ 同一个色值要在三个地方定义，最容易忘同步。**
`src/lib/theme.ts` 是真源；`index.html` 的内联脚本为了"首屏不闪"手抄了一份；
`src/styles.css` 的 `:root` 是兜底。**测试里加了一条逐字段比对**，抄错就红。

### 🔴🔴 自己踩的两个坑

**坑一：中文字符串里写 ASCII 双引号 —— 第三次了。**
`it("...否则"悬停没反应"，用户以为...")` → esbuild 直接 `Expected ")"`。
**规矩：中文注释和测试名里要引号，一律用「」。**
（前两次分别记在 §二·十 和更早的地方 —— 说明"知道"不等于"不会犯"，
所以这次加了个**写完就 grep 一遍**的习惯。）

**坑二：回归测试的正则会横跨规则块，把违规"吞"掉。**
第一版写的是 `^[^@\s][^{]*\{[^}]*color:...` —— 选择器部分 `[^{]*` 允许跨 `}`，
于是正则能从一个规则块的中间开始、一路吃到下一个块，
**把真正的违规包进前一条匹配里，导致一条都抓不到**。
当时跑出来"抓 0 条"，我差点以为"测试有效"。
**是拿改动前的样式表实测才发现：标称 0 条，实际该抓 47 条。**

> **教训（这条比上面所有都重要）**：
> **回归测试写完，必须拿"改动前"的输入跑一遍，确认它真的会红。**
> 一个永远不会失败的测试，比没有测试更危险 —— 它会让你以为有保护。

修法：选择器部分改成 `[^@\s}][^{}]*`（同时排除 `}`），实测改动前 47 条、改动后 0 条。

### 验证

- `tests/ui-contrast.test.ts`（第 31 科，16 条）—— 用真 WCAG 相对亮度公式，
  锁死 6 条不变量：实底字 ≥4.5、浅底字 ≥4.5、悬停 ≥3.5、三处定义逐字段一致、
  `--accent` 不许再当文字色、用到的变量必须有定义。

|---|---|
| 网页标签页 | `href="data:,"` —— **一个故意的空图标** |
| 桌面快捷方式 | 茶绿圆底 + 白对勾 `#0F766E`（跟产品紫完全无关） |

| 系统托盘 | 256px 图标硬缩到 16px |

**这个产品当时根本没有 logo。**

### 根因

图标是**四个地方各画各的**：`index.html` 一行、`desktop/scripts/make-icons.mjs` 一个常量、
三个 React 组件各引一个 lucide 图标。没有共同的真源，改一处另外三处不知道。

### 解法

`shared/brandSpec.mjs` 当**唯一真源**（纯数据 + 纯函数，**零 import** —— 因为构建机上
Node 20 直接读它，浏览器也要读它，两边都不能有依赖）。四条产物线全从它算：

- `scripts/make-icon.mjs` —— 4×4 超采样纯像素渲染（**只用 `node:zlib`**：
  构建机只 `npm install` 了 `desktop/`，根目录的 `sharp` 不一定在）
- `scripts/make-brand-assets.mjs` → `public/`；`desktop/scripts/make-icons.mjs` → `desktop/build/`
- `src/components/BrandMark.tsx` —— 页内 logo。**必须是 React 组件，不能是 `<img src>`**：
  img 里的 SVG 是独立文档，拿不到 `currentColor` 也拿不到 CSS 变量，会渲染成黑色。

### 🔴 这一轮真正的收获：抓出 4 类"看着像测试、其实什么都没验"的写法

**① `expect(a) || expect(b)` —— 右边永远不执行。**
`expect()` 断言失败会**直接抛**，短路之后 `||` 的右半边根本没机会跑。等于只检查了第一种写法。
```js
// ❌ 只验了 interface 写法，type 写法永远不看
expect(dts).toContain(`export interface ${t}`) || expect(dts).toContain(`export type ${t}`);
// ✅
const ok = dts.includes(`export interface ${t}`) || dts.includes(`export type ${t}`);
expect(ok).toBe(true);
```

**② `expect(cond || true).toBe(true)` —— 恒真断言。**
永远绿，什么都不验证，却看着像有覆盖。**写完断言先问一句"它有可能红吗"。**

**③ 哨兵查的是"子串"，不是"结构"。**
「品牌位不许用图标库清单符号」原本查 `toContain("BrandMark")` —— 把组件改名成
`ListTodoBrand` 照样包含这个子串，测试还是绿的。改成同时钉死**导入路径**
（`from "./BrandMark"`）+ **真实用法的尖括号**（`/<BrandMark[\s/>]/`）+ **反向断言**
（`not.toContain("<ListTodo")`）。

**④ 哨兵验的是"磁盘上已生成的文件"，不是"生成器现在会产出什么"。**
「favicon.ico 只打包 3 帧」原本读 `public/favicon.ico` —— 把生成脚本改回 7 帧、
忘了重新生成，磁盘文件还是 3 帧，测试照样绿。改成：**照脚本现算一遍 → 和磁盘文件比字节数**。

### 验收方法（这条是这轮最有价值的）

**写完哨兵，拿"改动前的输入"跑一遍，确认它真的会红。** 光写完不算数。
这轮一共验了 12 条，**抓出 2 条是假的**（上面 ③④）—— 不验的话它们会一直绿着，
下次有人改回去，没有任何东西会拦住。

### 另外两个自己踩的小坑

- **中文字符串里写 ASCII 双引号 —— 第四次犯。** 这次连自查都错了两回：
  `grep '[一-龥]"'` 全是噪音；"每行引号数是不是奇数"漏掉了引号数为**偶数**的那行。
  最终可用的正则：**两侧都是中文的那个引号**（`[中文]"` 且 `"[中文]`），
  且**先拿 esbuild 已经拒绝过的那一行验证扫描器真的会报**。
- **注释里的关键词会误伤哨兵**：`index.html` 里解释"为什么改掉 `data:,`"的注释本身
  含 `data:,`，整文件搜字符串就误报。改成只在真正的 `<link ...>` 标签里找。

### 图标本身的三个决定（都有实测依据）

1. **画吉祥物的脸，不画对勾。** 调研 11 个同类：对勾占 4 个（Todoist/Things/TickTick/MS To Do）
   是红海；11 个里只有多邻国用吉祥物。轻宜有桌宠常驻桌面，是产品真正的脸。
2. **纸白脸 + 深墨五官，不是深色脸挖白眼。** 第一版反过来做，ASCII 一渲染发现**和紫底糊成一坨**。
3. **耳朵挪到脸的边缘上。** App 里那两只耳朵整个在身体椭圆**以内**（`opacity .25`，
   只是块淡斑），32px 下只露 3 个像素。沿椭圆挪到边上才有"生物感"轮廓 ——
